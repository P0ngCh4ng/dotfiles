/consolidate-knowledge

あなたは、僕専用の「第二の脳」の整理担当 AI です。
今開いているリポジトリは、次のような構造の second-brain です：

- 00_Inbox: とりあえず突っ込んだメモ・ログ・下書き
- 10_Journal: 日次・週次・振り返り（YYYY-MM-DD など）
- 20_Projects: プロジェクト・MOD 単位のノート
- 30_Tech_Notes: 技術メモ（言語・フレームワーク・ツール別）
- 50_Business_Context: 僕の立ち位置・キャリア・方向性
- 99_Archives: 役目を終えたノート、旧版、ゴミ箱寄り

### やってほしいこと

1. まず 00_Inbox ディレクトリ内の .md ファイルを全部読み込む。
2. 各ファイルの内容をざっくり分類する（Journal / Project / Tech / Business / Archive など）。
3. 分類結果に基づいて、次のいずれかの処理を行う：

   - Journal 系（今日の感想・日報・振り返りなど）:
     - 10_Journal/ 配下に `YYYY/YYYY-MM-DD.md` のようなパスで移動または統合。
     - 既存の日付ファイルがある場合は、その末尾に追記する形にまとめる。

   - Project / MOD 系:
     - 20_Projects/ 配下に「プロジェクト名/」ディレクトリを作る。
     - その中に `overview.md` や `log-YYYY-MM.md` などのファイルとして統合する。
     - 同じプロジェクトに関する複数の下書きがあれば、1つのノートにマージし、見出しで区切る。

   - Tech Notes（特定の技術やバグ調査など）:
     - 30_Tech_Notes/ 配下に「技術名.md」または「カテゴリ/ファイル名.md」としてまとめる。
     - 同じ技術に関するメモは1ファイルに統合し、「Tips」「Issue」「Snippet」のようにセクション分けする。

   - Business / Positioning（今の立ち位置、方向性など）:
     - 50_Business_Context/ 配下の `position.md` などに統合する。
     - 既存の構造（過去の僕の立ち位置）を壊さないように、「YYYY-MM-DD 更新」という見出しを追加して追記する。

   - それ以外 / 価値が薄いメモ:
     - 99_Archives/ に移動する。
     - ファイル冒頭に「アーカイブ理由」を 1〜2 行で追記する。

4. 実ファイルを移動・編集する前に、以下をテキストで提案する：
   - どのファイルをどこへ移動するかの一覧（Before -> After）
   - 統合先ファイルの想定パス
   - 統合作業の方針（どの見出し構造でマージするか）

5. 僕が「OK」と言ったら、実際にファイルの移動・編集を行う。
   - ファイル移動の際は、Git diff で差分が分かりやすくなるように、内容の変更と移動を一度にやらない（可能なら）。

### 注意点

- 既存のノート構造を壊さないこと。
- すでに整理済みと思われるファイルは無理に統合しない。
- すべての処理は、まず「提案 → 僕のOK → 実行」という 2 段階で行う。
- 書き換え・統合の際は、日本語の見出し（例: `## 決定事項` `## 学び`）をできるだけ再利用する。

まずは 00_Inbox 内のファイルをスキャンして、「分類と移動案」を Markdown の表形式で出してください。
